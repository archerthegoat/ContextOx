# AlphaOx 路径七：本地工程化、开放扩展与可选服务化决策门详细开发计划

## 0. 计划状态与决策边界

- **状态**：`PROPOSED`，尚未开始实现。
- **目标**：把本地产品做成可诊断、可升级、可回滚、可扩展的交付物，并对未来服务化能力做独立评估。
- **首版边界**：本地单用户、回环服务、AlphaOx-owned 状态和受控数据工具。
- **服务化边界**：真实企业数据源、OIDC、多用户、共享 PostgreSQL、对象存储、队列和远程部署只做评估，不因评估而上线。
- **不授权事项**：不部署生产、不推送、不发布、不连接未经授权的真实数据、不开放写回。

## 1. 交付目标

路径七结束时，维护者应能回答：

1. 用户数据、运行状态、凭据、日志和报告如何备份、恢复、迁移和清理。
2. 本地运行失败时如何定位到服务、Runtime、Tool、Connector、模型或状态库边界。
3. 上游 Pi 如何同步，如何证明 Pi 变更没有穿透 AlphaOx 公共契约。
4. Connector、Context Pack 和 Controlled Data Tool 如何由第三方扩展而不绕过安全边界。
5. 什么时候有足够证据重新评估多用户服务化，而不是把本地产品直接暴露到网络。

## 3. 工程化契约

### 3.1 日志、Trace 与健康

- 每个运行关联 `workspace_id`、`run_id`、`trace_id`、策略/Context/Binding 版本、Provider、Tool、来源和状态。
- 日志只保留脱敏标识、错误类别、耗时、预算、重试/取消和状态转换。
- health 区分进程、本地状态库、Runtime、可选 Connector 和模型 Provider；外部来源失败不能伪装成本地服务健康。
- 用户可以导出最小化诊断包；导出前展示敏感字段类别并要求显式确认。

### 3.2 数据迁移与回滚

- 所有 SQLite migration 有版本、前置条件、校验、备份和失败恢复。
- 升级顺序为备份 → 预检 → migration → readback → 服务启动；任何一步失败保持旧版本可恢复。
- 不执行未经批准的破坏性删除；旧 Context、Binding、报告和 Evidence 引用保持可回看。
- 卸载默认只移除程序，不自动删除用户数据；删除数据必须单独确认且有范围提示。

### 3.3 上游 Pi 同步

- 在隔离分支读取 upstream，先检查 API、类型、事件、取消和工具生命周期变化。
- AlphaOx 只通过薄 Host adapter 消化 Pi 变化；公共 HTTP JSON/SSE、Tool、Result 和 Evidence 契约不随 Pi 私有类型漂移。
- 使用 fake Pi stream、未知事件、取消和 Provider 错误做回归；同步失败只阻断升级，不改写当前可用版本。

## 4. 可选服务化评估内容

每项评估必须单独记录目标、使用场景、数据分类、身份/权限、网络、存储、备份、成本、运维、可观测性、迁移、退出和责任人：

- 真实企业 Connector 和生产网络边界。
- OIDC、组织/角色、会话所有权和多用户缓存隔离。
- PostgreSQL 共享控制面、队列、对象存储和长任务恢复。
- TLS、远程监听、密钥托管、审计保留和数据写回。
- Docker/编排平台、水平扩展和发布回滚。

评估报告不是上线批准；只有另一个明确 Decision Gate 才能改变本地首版边界。

## 5. 验收要求

- 代码变更后运行适用包级测试和根级 `npm run check`；不执行未授权发布、推送或生产流程。
- 通过迁移失败、备份损坏、SecretStore 缺失、端口占用、SSE 断线、Provider/Tool 失败、日志脱敏失败和上游事件变化测试。
- 完成依赖锁定、供应链检查、安装 artifact 检查和敏感文件扫描。
- 路径五 Browser 清单必须在最终本地安装构建上重新执行；至少覆盖桌面/窄屏、键盘/焦点/滚动、加载/空/partial/blocked/error/stale、console/network、远程模型外发和范围化清理。
- 所有 `BLOCKED` 必须有外部依赖、责任人、复现条件和重新执行条件。

## 6. 分支、commit 与回滚

- 从 `main` 使用 `codex/alphaox/pass-07`；切片使用 `codex/alphaox/pass-07-<slice>`。
- 每个阶段完成后提交明确文件，检查 staged 路径和测试证据，再进入下一阶段。
- 本地升级可回退到上一个应用/Schema 版本；服务化评估不会改变本地配置或开启远程监听。
- 所有 Pass 集成、架构和 Browser 证据展示完毕后，才由人类决定是否合入 `main`。

## 7. 人类 Decision Gate

路径七的最终门必须确认本地安装、数据保留、凭据、升级/卸载、上游同步、扩展契约、服务化评估和 Browser 证据均真实可读。任何评估结论不得直接转化为生产授权。
