# AlphaOx 路径一：仓库治理与架构基线详细开发计划

## 0. 计划状态与边界

- **状态**：`COMPLETED`，历史计划索引。
- **目标**：建立独立仓库、分支治理、架构边界、正式架构图和完整验收清单。
- **权威证据**：[架构与验收报告](../架构与验收报告.md)及其 ArchScribe 工件。
- **实现边界**：本路径只交付治理、架构文档和图形工件，不实现 Web、真实 Connector、模型调用或生产部署。
- **回滚边界**：文档和图形工件可回退到路径一已验收 commit；未创建数据库、凭据、真实数据或外部资源。

## 1. 交付目标

路径一结束时必须能回答：

1. AlphaOx 的产品责任与上游 Agent Runtime 责任如何分离。
2. 计划、权限、执行、证据、状态、新鲜度和报告的边界是什么。
3. 后续路径如何从当前基线继续，哪些能力明确不在路径一。
4. 人类如何在未来 Browser 中验收工作台，而不把架构图渲染误判为产品通过。

## 2. 分阶段计划

| 阶段 | 交付 | 通过条件 | commit 门 |
| --- | --- | --- | --- |
| 1.1 | 独立仓库、origin/upstream、main 和 Pass 分支规则 | 仓库来源、分支祖先、工作区和未推送边界可读回 | 只提交本阶段明确文件 |
| 1.2 | 组件职责、契约、权限、状态、失败和回滚决策 | 目标、事实、替代方案、风险和所有权写入报告 | 人类架构讨论后提交 |
| 1.3 | ArchScribe 规范源 | JSON Schema/规范校验通过，布局容量无警告 | 规范源单独检查后提交 |
| 1.4 | PNG、SVG、Excalidraw、HTML | 先视觉检查 PNG，再运行严格格式检查；不生成 GIF/MP4 | 图形工件和源文件一起提交 |
| 1.5 | 完整 Browser 验收清单和对抗复核 | 清单含构建、起始状态、单标签、URL、视口、数据、操作、状态、可访问性、网络、清理和证据栏 | Decision Gate 前不得合并 |
| 1.6 | PASS 01 集成 | 最终差异、验收证据、风险、回滚和人类批准完整 | 只在批准后合并 main |

## 3. 核心边界

- AlphaOx 自有权限、计划、执行、证据和报告边界不能由上游 Agent Runtime 代替。
- 模型不能生成或执行任意 SQL、代码或写操作。
- 真实企业数据、生产身份、外部写回、Docker 生产编排和 Browser 产品验收不属于本路径。
- 图形渲染检查不等于产品 Browser 检查；后者保持 `NOT RUN`，直到路径五实现。
- 路线图由人类控制，任何变更先展示精确 diff；路径一不能自动回写路线图。

## 4. 验收证据

- [架构与验收报告](../架构与验收报告.md)包含决策、拒绝方案、契约、失败矩阵、边界、迁移/回滚、维护责任和 Browser 清单。
- [ArchScribe 规范](../architecture/alphaox-system-architecture.spec.json)是图形源。
- PNG、SVG、Excalidraw 和 HTML 是派生交付物；派生工件必须能由规范重复生成。
- 正式工件检查通过不代表路径四、五的 Runtime 或 Web 功能已实现。

## 5. 未决事项

后续本地优先架构修订需要重新确认：产品是否以本地单用户为首版、Runtime Host 与 Pi 的边界、持久化和凭据方案、默认回环服务、模型上下文外发、可选 Docker 以及新的图形叙事。路径一的历史结论不能自动覆盖这些新决策。
