业务范围为 demo-commerce/e1；本次模拟 Case 为 case-01。原始事实视图固定在 2026-07-01T00:00:00Z，覆盖 [2026-04-01T00:00:00Z, 2026-07-01T00:00:00Z)。这不是当日经营数据，也不保证反映客户全部历史。

这里的“高潜”仅是待裁决的运营定义，不等同于未来购买概率、信用或终身价值。维护周期、资源容量与最终规则尚待业务裁决者确认；可提出候选方案，不预设权重、阈值或唯一名单。若方案不依赖某项未知，不必为了演示强制发问；必要事实或当前授权缺失时不能直接补造结论。

期望交付是有依据的候选规范、映射、样例、未知与待裁决事项，获得有效批准后才有首份 Contract v1。本资料包自身没有已批准 Contract，也不授权发布、客户触达、营销或任何外部写入。

## 3. 字段字典与读取语义

所有标识均为中性合成标识，不是姓名、电话、地址、账号或客户标签。JSON 是本包的材料格式，不是产品公共 API、数据库 Schema 或已批准的业务规则。

共同字段：

- source_ref：本包的合成来源标识；src-customers、src-orders、src-items、src-payments、src-fulfillment 各自拥有对应事实组。
- source_version：该条合成事实的来源版本。本快照每个业务记录仅有一个可见版本；历史副本/更新须保留版本，不能原地改旧快照。
- available_at：在合成时钟下该版本何时可获得，不是文件写入时间；只在 available_at ≤ as_of 时可用于相应视图。
- metadata：包内格式/快照、合成来源与生成方式、实际编制时刻、业务范围、as_of、覆盖窗、时区和单位。source_snapshot_version 为合成来源快照版本，不是 Contract 版本。

| 事实组 / 一行粒度 / 本快照键 | 组内字段与含义 | 注意事项 |
|---|---|---|
| customer_links：一个订单侧键到业务客户的映射；order_customer_ref | customer_ref 为业务客户键；mapping_basis_ref 指向 ctx-map-r1；effective_from / effective_to 为本映射适用区间 | 映射键可以多对一；不能直接用订单侧键数客户。早于订单观察窗但仍适用的映射保留 |
| orders：一笔订单的可见版本；order_ref | order_customer_ref 关联映射；purchased_at 为购买事件时间；status_at_snapshot 为当时可见状态 | registered 仅表示已登记，不暗示已交付；delivered 仅对已有相应来源事件的订单使用。订单状态版本有自己的 available_at |
| items：一个订单内商品行；item_ref | order_ref；goods_amount_minor 为货品行总额；freight_amount_minor 为独立运费行总额；currency；time_basis_ref | 金额不是单价，不再乘数量。货品与运费分别汇总；不得在商品与支付联结后重复计数 |
| payments：一条独立收款；payment_ref | order_ref；received_amount_minor；currency；paid_at 为该条收款业务时间 | 可能拆分收款，也可能未全额收齐；不能直接将收款命名为净收入 |
| fulfillment_events：一次独立登记事件；event_ref | order_ref；event_type；event_at 为事件时间 | registered / delivered 仅描述所列事件；缺少某类事件与确认未发生不同 |

主快照使用 UTC，金额均为 CNY 整数分，1 元 = 100 分；不能跨币种直接相加或自行假设汇率。商品、支付和履约都是订单的一对多关系，应各自在正确粒度聚合后再组合；订单商品额与收款额不设一般恒等关系。

业务事件按覆盖窗起点包含、终点不包含读取；可获得时点包含 as_of 本身。映射按其适用性而不是订单观察窗起点过滤。没有可信业务时间、父子依据或版本可获得时间时保留未知，不人为补日期。固定事实视图不等于当前动作仍有权限。
